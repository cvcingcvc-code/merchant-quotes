# 商家电脑安装预检

适用于 Node.js 方式的安装和排障。在商家首次启动、升级后的独立测试副本或启动报错时使用。Docker 方式请按 README 的 Docker 步骤核对，不以宿主机上的本命令代替容器验收。

## 使用

在项目目录先安装依赖，然后执行预检：

```bash
npm ci
npm run doctor
```

先处理所有失败项，再启动本机服务 `npm start`，或运行手机演示启动器 `npm run demo:lan`。若当前已启动本工具，预检可能报告端口被占用；确认进程和地址后直接访问已有服务，不要自动终止不明进程。

没有 `.env` 时，默认只监听本机；手机演示启动器会在没有已有配置和环境密码时生成访问密码。已经存在 `.env` 时，启动器不会覆盖它：如需手机访问，请自己设置至少 12 位 `APP_PASSWORD`，不要把密码粘贴到问题单或提交到 GitHub。

## 检查内容

| 项目 | 检查范围 | 常见处理 |
| --- | --- | --- |
| Node.js | 使用项目要求的 Node.js 24 | 安装 Node.js 24 后重新打开终端，再执行 `npm ci` |
| 配置 | 校验端口、演示开关和对外监听时的密码条件；环境变量优先于 `.env` | 修正 `.env` 的对应字段，保留其他原有配置 |
| 数据目录 | 检查目录及已有数据库文件的权限；不存在时检查可创建它的父目录 | 由商家或安装人员确认目录与权限，不删除原数据库 |
| 备份目录 | 检查已有备份目录是否可使用 | 核对磁盘权限与目录类型；保留已有备份 |
| 运行库与 SQLite | 加载实际应用依赖，在内存中使用虚构资料检查 SQLite | 在同一 Node.js 版本和系统上执行 `npm ci`，不要跨电脑复制 `node_modules` |
| 中文 PDF | 核对随项目提供的原版字体完整性，并用真实 PDF 生成器在内存生成虚构报价 | 核对完整源码与字体文件，再重新安装依赖；本版本不支持直接替换字体 |
| 端口 | 短暂监听并关闭配置端口，检查本机能否绑定该地址 | 确认是否已有服务运行，或修改 `.env` 的 `PORT`；不强制关闭占用者 |

目录权限检查不读取客户、报价或备份正文；SQLite 和 PDF 自检不使用商家的文件数据库，也不将虚构记录写入正式数据。命令不修改 `.env`，不创建或清空数据目录，不购买服务，也不启动正式应用。

通过内存 PDF 检查，表示生成器和字体可运行；手机是否能下载、打开和转发 PDF，需要实际手机操作。权限预检也不代表磁盘空间足够、网络文件系统适用或断电恢复已验收。

## 输出与受限环境

终端显示每项通过、提醒、失败或跳过结果。失败时退出码为 1。提醒和跳过仍需阅读，不能只凭退出码认定完成交付或生产可用。

自动记录结果时，可直接运行：

```bash
node scripts/doctor.js --json
```

JSON 不输出访问密码或客户资料。传递诊断结果前仍应由商家核对授权范围。

有些执行环境禁止本地监听。仅排查其他项目时可以明确跳过端口检查：

```bash
npm run doctor -- --skip-port
```

被跳过的端口项不会记作通过。正式启动前，需在实际运行电脑上执行不带此参数的预检。若是权限限制，也不能把它误当作端口占用。

## 交付后仍需人工完成

在商家自己的电脑上实际启动，使用同一 Wi-Fi 的真实手机完成 [演示清单](PHONE-DEMO.md)，核对中文 PDF、重启后的记录与异机备份，再填写 [交付单](HANDOVER.md)。本轮自动化不能代替 Windows / macOS 真机安装、iPhone / Android 验收或实际付款验证。

2026-10-24 的 Linux / Node.js 24 自动化结果：40 项单元/API 与 8 项浏览器测试通过，包含 16 项安装预检回归和受控配置下的实际端口探测。详细检查结果与源文件校验值见 [验证记录](evidence/install-preflight-verification.json)。
