# 首批付费试用方案草稿

本方案面向广告图文店、独立设计工作室等需要逐单报价的商家，采用单商家一次性交付。它是可调整的试售假设，**价格、付费意愿和留存均未经过市场验证**，不代表已有人购买或保证能获得收入。对外报价前，由交付负责人确认本页范围和实际可支持的设备。

首次配置、安全清理示例、复制报价、主动更新报价资料和自动日备份等能力，须由本次发行的实际验收证明后才能承诺。以交付单填写的版本、设备和验收结果为准，不能仅凭本方案认定功能已就绪。

## 试售对象与交付方式

- 优先服务已有明确商品或服务项目、现在通过微信、纸笔或 Excel 逐单报价的商家。
- 首批以一台商家自己的电脑运行、同一 Wi-Fi 的手机访问为默认方案；也可由双方确认使用商家已有的单台 Docker 主机。
- 安装服务只覆盖交付单记录的一套运行环境。源码按项目 MIT 及第三方许可证提供；收费对应配置、培训和限定售后，不宣称独占软件许可。
- 不因试售自动购买服务器、域名、证书服务或其他收费资源。远程公网访问须单独确认已有主机、HTTPS 和维护责任。

## 建议测试价

**399 元 / 商家，一次性交付。** 这是首批验证价，可根据实际安装和售后成本调整，不是市场定价结论。

建议先提供一次不超过 20 分钟、只使用虚构资料的演示；确认设备适配、交付范围和收费方案后再安排安装。主流程验收通过、商家确认签收后，再按双方线下约定办理收费。本工具不处理付款，不接入支付账户。未通过约定验收的，不记作成功交付或付费验证。

## 399 元建议包含的范围

| 项目 | 服务边界 |
| --- | --- |
| 一套安装 | 一台事先确认可支持的电脑，或一台商家已有的 Docker 主机；不含购买设备和云资源 |
| 一次商家配置 | 填写商家名称、联系人、地址和报价条款，确认访问密码，完成演示资料与正式资料的切换 |
| 一次流程培训 | 最多 30 分钟，使用虚构客户完成客户管理、报价、中文 PDF、跟进和备份演示 |
| 标准报价功能 | 本次已验收版本的报价新建、编辑、复制、金额计算、固定版式中文 PDF，以及三种跟进状态 |
| 一次恢复演练 | 从演示备份恢复到独立演示环境，核对金额和跟进记录；不擅自替换商家正式数据 |
| 限定使用协助 | 自签收日起 30 个自然日内，最多 2 次远程协助，每次最多 30 分钟，提前约定时间 |
| 已约定功能的缺陷处理 | 30 天内对约定主流程中可复现的问题进行定位和修复；不将已确认的程序缺陷处理扣作培训次数 |

使用协助可以覆盖重新连接同一局域网、查找备份、按文档重启、理解已有设置等问题。建议以 1 个工作日内回复为服务目标，具体处理时间按问题确认；卖方应先确认自己能履行该目标，再对外承诺。

## 建议不包含的范围

- 多店、多租户、员工角色、在线支付、分销、会员、积分和获客承诺。
- 发票开具、税务判断、电子签章、法律效力认证、库存和财务系统。
- 任意样式的 PDF 模板设计器、无限次改版，以及商家未在验收前确认的额外定制。
- 代购或长期托管服务器、域名、宽带、电脑、打印机、HTTPS 服务。
- 全天候在线值守、硬件维修、第三方软件故障处理，以及设备断网或关机时的可用性保证。
- 无边界的数据清洗、批量导入、旧系统迁移或永久人工代备份。

超出范围的培训、设备迁移和定制需求，应先说明工作量并单独报价，双方确认后再做。30 天服务期到期后不自动续费，不默认产生长期维护义务。

## 演示脚本：用一份报价证明价值

全程使用“演示验收商店”等虚构客户，不先索取真实客户名单。

1. **了解当前操作，约 2 分钟。** 请商家描述最近一次报价如何制作、发送、修改和跟进；记录实际问题，不预设“必然提高成交率”。
2. **首次设置，约 2 分钟。** 演示商家抬头、条款和正式使用入口，说明清理示例时如何保护新增或已修改记录。
3. **开一份单，约 4 分钟。** 新增虚构客户，输入 `3 × 19.90` 和 `1.5 × 100.05`，核对逐项金额及合计 `¥209.78`。
4. **发送前核对，约 2 分钟。** 下载中文 PDF，查看抬头、客户、日期、项目、合计和条款。在手机文件应用里实际打开，不能用电脑上的 PDF 代替这一项验收。
5. **处理下一份单，约 2 分钟。** 复制报价成新单，展示新编号和待回复状态；原单及其跟进历史保持不变。演示更正资料时仅主动更新当前报价。
6. **合作进展，约 2 分钟。** 保存已成交状态、下次跟进日期和备注，停止并重新启动服务，核对记录仍在。
7. **资料可带走，约 3 分钟。** 展示手动导出、运行期间的自动日备份和下载列表；说明商家每天还需把备份复制到另一设备。
8. **验证意愿，约 3 分钟。** 请商家自己完成一次关键操作，再询问是否愿意按已说明的交付范围付费。把“不购买的原因”与实际付款分别记录。

如果某一项在本次发行尚未通过验收，演示前就从承诺范围移除或先修复，不以口头说明代替实际操作。

## 首批验证目标

建议把第一个验证批次设为 3 家实际付费商家，安装后在第 3 天和第 7 天进行使用回访。它是行动目标，不是收益预测；不要把朋友称赞、免费试用、下载量或口头愿意购买记作付款。

每家至少记录：是否实际付款、是否独立生成并发送过报价、过去 7 天使用次数、遇到的问题，以及卖方为此付出的安装和售后时间。无需在软件中添加统计追踪；可使用商家同意提供的匿名回访记录。

判断能否继续销售时，同时看实际到账、实际使用和交付成本。例如 399 元成交但需要多次上门处理，也应记录成本并调整支持范围，而不能只统计销售额。

## 对外报价前核对

- [ ] 填好本次发行版本和交付设备，已实际完成 [交付验收单](HANDOVER.md)。
- [ ] 演示中的每项能力均已通过当前版本验收，手机上的 PDF 下载已检查。
- [ ] 商家知道本地电脑需保持运行，局域网地址不等于公网链接。
- [ ] 价格、服务期限、协助次数、额外需求和收费时间已明确。
- [ ] 没有把开源源码误说成独占许可，没有作营收或成交率保证。
- [ ] 安装、远程协助和资料查看均取得商家授权，未索取无关客户数据。
